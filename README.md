# 날씨지수 프로젝트: 수집·분석 코드

날씨(난방도일·냉방도일·폭염일수·기온)가 업종별 분기 실적과 주가에 주는 영향을 회귀계수로 정리합니다.

## 1. 준비 (처음 한 번)

```bash
pip install -r requirements.txt
copy .env.example .env      # 맥/리눅스는 cp .env.example .env
```

`.env`에 키를 넣습니다. **키는 채팅·카톡·깃허브에 절대 올리지 마세요.** 노출되면 바로 재발급해야 합니다.

| 키 | 용도 | 발급처 | 필수 여부 |
|---|---|---|---|
| `DART_API_KEY` | 분기 매출·영업이익 | opendart.fss.or.kr → 인증키 신청 | 필수 |
| `ECOS_API_KEY` | 도시가스 요금(물가) 통제 | ecos.bok.or.kr (이미 보유) | 선택 |
| `DATA_GO_KR_KEY` | 기상 일자료 API | data.go.kr → "기상청_지상(종관, ASOS) 일자료 조회서비스" 활용신청 | 아래 둘 중 하나 |

**기상 자료는 둘 중 하나만 하면 됩니다.**
- (a) 키 없이: 기상자료개방포털(data.kma.go.kr)에서 종관기상관측(ASOS) **일자료**를 CSV로 내려받아 `data/raw/kma/`에 넣습니다.
  지점 8곳(서울108·인천112·수원119·대전133·대구143·울산152·광주156·부산159), 기간 1985-01-01~2025-12-31,
  요소는 평균·최저·최고기온. 기간 제한이 있으면 여러 파일로 나눠 받아도 됩니다(자동으로 합칩니다).
- (b) `.env`에 `DATA_GO_KR_KEY`를 넣으면 API로 자동 수집합니다.

## 2. 실행

```bash
python -m pytest -q tests       # 스모크테스트 (37개 통과해야 정상)
python run_collect.py           # 수집 -> data/raw/*.csv
python run_analysis.py          # 분석 -> output/report.md, results.csv, oos.csv
python run_stress.py            # 스트레스 테스트 -> output/stress_report.md
python run_swi.py               # Stock Weather Index -> output/swi_report.md
```

일부만 수집하려면 `python run_collect.py weather dart` 처럼 단계를 적습니다.

**분석까지 제가 하길 원하면 `data/raw` 폴더의 CSV 파일들을 채팅에 올려주세요.** (`.env`는 올리지 마세요.)


## 4. 모형과 그렇게 정한 이유

- **결과변수**: 전년 동분기 대비 매출 로그성장률, 영업이익 변화(전년 동분기 매출 대비), 분기 초과수익률(KOSPI 대비), 다음 분기 초과수익률.
  전년 동분기와 비교하면 계절성이 자동으로 빠집니다. 영업이익은 음수가 될 수 있어 로그 대신 매출로 나눕니다.
- **날씨변수**: 결과가 전년 대비이므로 날씨도 전년 동분기 대비 변화(ΔHDD, ΔCDD, Δ폭염일, Δ기온)로 맞춥니다.
  의류·유통은 따뜻한 겨울과 따뜻한 봄의 효과 방향이 다르므로 기온 변화를 분기별로 나눠 넣습니다.
- **평년**: 해당 연도 이전 30년만 씁니다(미래정보 배제). 테스트에서 미래 값을 바꿔도 평년이 변하지 않는지 확인합니다.
- **고정효과**: 기업 고정효과 + 분기더미. 코로나 같은 연도별 충격을 걸러낸 연도더미 버전도 함께 냅니다.
- **표준오차**: Driscoll-Kraay. 업종당 기업이 4~6개뿐이라 기업 클러스터 표준오차는 믿기 어렵고,
  같은 업종 기업들이 같은 날씨 충격을 공유해 오차가 시점별로 상관되기 때문입니다.
- **검증**: 2021년까지로 추정하고 2022년 이후를 예측해, 날씨를 넣었을 때 예측오차가 줄었는지(oos_gain) 봅니다.
  여러 업종·지표·결과를 한꺼번에 검정하므로 Benjamini-Hochberg 보정 p값(p_bh)을 같이 봅니다.
- **데이터 품질**: 기상 이상치(최저>최고 등)나 0 이하 매출이 있으면 분석을 멈춥니다. 분기 결측일이 10%를 넘으면 그 분기는 NaN입니다.

## 4-1. 사전 등록 판정 (2026-11-09, 실데이터 결과를 보기 전에 고정)

결론은 `config.py` 의 `PREREG_*` 로 미리 정한 기준 하나로만 냅니다. 나머지 회귀·백테스트 표는 탐색 자료입니다.

| 단계 | 무엇을 | 통과 기준 |
|---|---|---|
| 제외 규칙 | 국내 매출 비중 < 50% 종목 제외 (현재 미스토홀딩스만 해당, 근거는 config 주석) | — |
| 1차 (주 결과) | 업종마다 검정 1개: 가스 ΔHDD(+), 음료 ΔCDD(+), 의류·유통 4분기 Δ기온(−) → 매출 성장률. 기업FE+분기·연도더미 | 연도 순열검정(999회) 단측 p를 4개 업종에 BH 보정 q ≤ 0.10, 부호 일치 |
| 2차 | 1차 통과 업종만으로 SWI 업종 내 롱숏(왕복 30bp 차감), 평가구간 | Newey-West t ≥ 2 |
| 일본 자료 | 한국 유효 분기 < MIN_FIRM_OBS 인 업종에만 참고값으로 표시, 점수·판정에 안 섞음 | — |

- 산출물: `output/prereg_stage1.csv`(run_analysis), `output/prereg_stage2.csv`(run_swi), 보고서 맨 위 '사전 등록 판정' 절.
- 제외 종목을 포함한 참고 버전: `set SWI_INCLUDE_EXCLUDED=1` 후 실행.
- 기준을 바꿔야 하면 날짜·이유를 남기고, 바꾸기 전 결과도 함께 보고합니다.
- 2026-11-09 변경(실데이터 결과 보기 전): p값을 Driscoll-Kraay t 에서 연도 순열검정으로 교체.
  합성 날씨(효과 없음)에서 DK 는 '하나라도 통과' 35%, 순열은 11%(명목 10%). 근거·재현: `tools/README_calibration.md`.
  연도 순열검정 = 날씨값을 해 단위로 다른 해와 바꿔 끼워 '날씨와 실적이 무관할 때의 계수 분포'를 직접 만드는 방법.

## 5. 알고 있는 한계 (결과 해석 시 주의)

- 종목코드는 상장명과 자동 대조합니다. 다르면 그 종목은 수집하지 않으니 `config.py`를 고쳐주세요.
- 롯데웰푸드(2022 롯데푸드 합병), 이마트(연결 범위 변화) 등은 합병·연결범위 변화가 있어 해당 시점 성장률이 튈 수 있습니다.
- 미스토홀딩스(옛 휠라홀딩스, 2025-04 사명 변경)는 사전 규칙(국내 매출 50% 미만 제외)으로 분석에서 뺐습니다. 수집은 계속합니다.
- 도시가스 매출은 요금 조정 영향이 큽니다. ECOS 키가 있으면 도시가스 물가 변화를 통제변수로 넣습니다.
  ECOS 통계표 코드(901Y009, 품목별 소비자물가)는 확인이 필요하며, 다르면 `collect/ecos.py`에서 바꿉니다.
- 전국형 기업은 6개 도시 평균 날씨를 씁니다. 실제 매출 지역 비중과 다를 수 있습니다.

## 6. 날씨 리스크 스트레스 테스트 (`run_stress.py`)

"내년 날씨가 나쁘게 흘러가면 업종 실적이 얼마나 줄어드는가"를 분포로 계산합니다.

1. **기온 모형 추정** (`core/weather_sim.py`): 지점별로 `기온 = 추세 + 계절평균 + 분기충격 + 일 단위 OU 변동`.
   지점 간 상관(일 단위·분기 단위)을 함께 추정합니다.
2. **몬테카를로**: 대상 연도를 5,000번 시뮬레이션해 분기별 난방도일·냉방도일·폭염일·평균기온 분포를 만듭니다.
3. **실적 영향**: 회귀계수(run_analysis 결과) × (시나리오 날씨 − 기대 날씨) × 기준 매출.
   계수의 추정오차도 경로마다 반영합니다. 같은 업종에 지표 두 개를 동시에 쓰지 않습니다(이중계산 방지).
4. **위험 지표**: 기업·업종·동일가중 포트폴리오별 날씨 VaR·ES(95%, 99%)
5. **시나리오**: 계절평균 +1℃ 기후 이동, 과거 각 연도의 평년 대비 날씨를 지금 실적 규모에 재현한 역사적 스트레스
6. **생성기 검증**: 2010년까지로 추정한 모형이 이후 실제 분기 지수를 90% 구간에 담는지 Kupiec 검정.
   일 단위 OU만 쓴 모형과 분기충격을 더한 모형을 함께 비교합니다.

**분기충격을 넣은 이유:** 일 단위 OU만 쓰면 편차가 며칠 안에 사라져 "분기 전체가 따뜻한" 상황의 확률을 과소평가하고,
분기 지수 분산이 작아져 VaR이 낮게 나옵니다. 가상 데이터 시험에서 OU만 쓴 모형은 실제값이 90% 구간 밖으로 72% 나가
기각됐고, 분기충격을 더한 모형은 13% 수준이었습니다. 이 가상 데이터는 분기충격을 넣어 만든 것이라 개선 폭이 실제보다
크게 보일 수 있으며, 실제 기상 자료로 다시 확인해야 합니다.

**주의:** 회귀계수가 유의하지 않은 업종(보고서 2-0 표의 p_bh가 큰 경우)의 VaR은 추정오차만 반영된 값이라 참고용입니다.

## 7. Stock Weather Index (`run_swi.py`) — 시제품

```
[1층 입력]  기상정보(기온·강수·한파)  기업정보(업종·지역·매출)  금융정보(주가·거래량)      swi/inputs.py
[2층 엔진]  기상 민감도(부분 풀링) · 예보 변화(관측+평년) · 수익률 학습(로지스틱 vs GBM)  swi/engine.py
[3층 지수]  기상수혜도 B · 상승확률 P · 신뢰도 C → 종합 SWI (0~100)                    swi/index.py
[4층 활용]  관심종목 · 위험경고 · 상/하위 포트폴리오 백테스트                           swi/decision.py
```

- **매월 말 산출.** 그 시점에 알 수 있던 정보만 씁니다: 분기 중 관측된 달 + 남은 달 평년값, 분기말+90일 지난 실적, 월말 종가.
- **기상수혜도 B**: 종목 민감도 × (이번 분기 예상 날씨 − 작년 같은 분기). 50이 중립.
- **신뢰도 C**: 민감도 추정오차와 남은 기간 날씨 불확실성을 함께 넣어, 수혜 방향이 맞을 확률을 0~100으로.
- **상승확률 P**: 다음 달 시장 대비 상승 확률. 로지스틱과 GBM을 월별 워크포워드로 돌리고, 표본외 앞 36개월로 모델을 고른 뒤
  나머지 기간으로만 평가합니다. 같은 모델을 날씨 변수 없이도 돌려, 날씨가 예측을 실제로 개선하는지 AUC 차이와 부트스트랩 구간으로 확인합니다.
- **4층 백테스트**: B, P, SWI 각각으로 상위 1/3 − 하위 1/3 포트폴리오의 다음 달 초과수익률, Newey-West t값, 회전율, 거래비용 반영 성과.

**가상 데이터 시험 (실제 시장 성과 아님)**
- 도시가스 종목 주가가 날씨 수혜에 반응하도록 심은 데이터: 평가구간 SWI 상·하위 스프레드 월 +1.3%(t=3.2),
  날씨 변수 추가 시 AUC +0.047 (90% 구간 0.026~0.070) → 심은 효과를 찾아냄
- 날씨 효과가 없는 데이터: 유의한 양(+)의 성과 없음(평가구간 SWI t=−0.8), 날씨 변수가 오히려 AUC를 낮춤 → 없는 효과를 만들어내지 않음

**아직 없는 것**: 실제 기상청 예보 이력(현재는 '남은 달 평년'으로 대체), 실제 공시일(현재 90일 보수 가정), 애널리스트 컨센서스.

### 7-1. 개선 (2026-11-08)

1. **도시가스는 판매량으로 민감도 추정** (`swi/volume.py`, `config.GAS_REGION`, `SWI_GAS_USE_VOLUME`)
   도시가스 매출은 원료비 연동 요금 변화에 크게 좌우되어 날씨 효과가 묻힙니다. 날씨가 직접 움직이는 판매량을 씁니다.
   - 준비: KOSIS(국가통계포털)에서 '도시가스 판매량' 시도별·월별 표를 내려받아 `data/raw/citygas_volume.csv`로 저장하고
     열 이름을 `region, ym, volume`으로 맞춥니다 (예: 서울, 2024-01, 123456). 정확한 통계표 이름은 포털에서 확인하세요.
   - 지역 합계라 그 지역의 다른 공급사 물량도 섞인 근사치입니다. 지역난방공사는 지역 판매량이 없어 매출을 그대로 씁니다.
   - 파일이 없으면 자동으로 이전처럼 매출을 씁니다. 보고서 '민감도 결과변수' 표에 종목별 출처가 나옵니다.
2. **공시일 이벤트 스터디** (`swi/event.py`, `run_collect.py disclosure`)
   날씨 수혜가 주가에 '분기 중 / 공시 전후 / 공시 후' 중 언제 반영되는지 회귀로 확인하고 자동 판정합니다.
   공시 이후에도 반응이 남아야(지연 반응) 날씨로 주가를 예측할 근거가 생깁니다. 공시일은 DART 잠정실적·정기보고서에서
   가장 이른 날을 쓰고, 없으면 분기말+45일로 가정합니다(보고서에 출처 표시).
3. **업종 안에서 비교** (`SWI_WITHIN_GROUP`)
   수혜도 점수의 잣대를 업종별로 따로 잡고, 포트폴리오도 업종 안에서 상·하위를 만듭니다. 전 종목을 한 줄로 세우면
   '계절별 업종 갈아타기'가 섞여 종목 선택 능력을 볼 수 없기 때문입니다. 보고서에는 이전 방식과 업종별 결과도 같이 나옵니다.

## 8. 운영 시스템 (`swi_system.py`) — 매일 자동으로 돌아가는 Stock Weather Index

```
[매일 07:30]  관측(ASOS) + 주가 + 중기예보 스냅샷 수집 → DB → 품질 점검 → 오늘의 지수 → DB
[매월 2일]   실적·공시일·물가 갱신 → 백테스트·이벤트 스터디 → 상승확률 모델 재학습·저장 → DB
[언제든]     대시보드: 오늘의 지수 · 종목 상세(날씨 분해·추이) · 검증 결과 · 시스템 상태
```

처음 한 번:
```bash
pip install -r requirements.txt
python swi_system.py init        # data/swi.db 생성
python swi_system.py backfill    # 과거 전체 수집 → DB 적재 → 월간 작업(모델 학습)
python swi_system.py daily       # 오늘의 지수 (기본: 어제 기준, --asof 2026-11-10 처럼 지정 가능)
python swi_system.py dashboard   # 브라우저에서 대시보드 열림
scripts\register_windows_tasks.bat   # 매일·매월 자동 실행 등록 (윈도우)
```
맥은 `crontab -e`에 `30 7 * * * cd /경로/weather_index && python swi_system.py daily` 와
`0 8 2 * * cd /경로/weather_index && python swi_system.py monthly` 를 추가합니다. PC가 켜져 있어야 실행됩니다.

**일별 지수의 날씨 = 관측 + 예보 + 평년** (`system/nowcast.py`)
- 분기 시작~어제: 실제 관측 / 3~10일 뒤: 기상청 중기기온예보 / 그 이후: 직전 30년 같은 날짜 평균(앞뒤 15일로 다듬음)
- 불확실성: 평년 구간은 과거 같은 기간 합계의 변동, 예보일은 예보 오차.
  `python run_collect.py forecast_err` 로 예보 이력 vs 관측에서 리드별 편향과 리드 간 오차 공분산을 만들면
  (`data/processed/forecast_err_model.csv`) 자동으로 편향을 빼고, 분산은 공분산까지 더합니다(1'Σ1).
  예보 오차는 며칠씩 같은 방향으로 틀리므로 '하루 오차² × 일수'(독립 가정)는 불확실성을 과소평가합니다. 파일이 없으면 기본 2℃ 독립 가정.
- 2024-11 이후 중기예보는 4~5일 뒤부터 시작합니다. 그 앞 며칠(단기예보 구간)과 1·3개월 장기전망은 아직 연결하지 않았습니다(평년으로 대체).

**품질 점검에서 멈춤**: 기상 관측이 5일 넘게 멈추거나, 최저>최고 같은 이상치가 있거나, 주가가 7일 넘게 갱신되지 않으면
그날 지수를 내지 않고 실행 이력에 'halted'와 사유를 남깁니다. 대시보드는 마지막 정상 결과와 경고를 함께 보여줍니다.

**예보 이력**: 기상청 API허브에서 2015년 이후 중기 기온예보 이력을 받습니다(`run_collect.py forecast_hist`).
예보구역 코드(`config.FORECAST_REG`)는 기상청 예보구역 목록과 대조하는 테스트가 있습니다.
