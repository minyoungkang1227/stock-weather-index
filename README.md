# Stock Weather Index — 날씨·예보 기반 업종 영향 분석 시스템

날씨(관측·기상청 예보·평년)와 기업·금융 정보를 묶어 업종별 날씨 영향을 측정하고, 종목별 0~100 지수로 보여 주는 시스템입니다.
구조는 다음 아키텍처(기상·기업·금융 정보 → AI 엔진 → Stock Weather Index → 투자 의사결정 지원)를 따릅니다.

> **실데이터 결론 (2026-11-09)** — 자세한 근거: [말할 수 있는 것과 없는 것](docs/결론_말할수있는것_없는것.md)
>
> | 검정 (결과 보기 전에 기준 고정) | 결과 | 판정 |
> |---|---|---|
> | 날씨 → 도시가스 **판매량** (7개 시도, 2015~2024) | 난방도일 100당 +5.2%, p = 0.001 | ✅ 확인 |
> | 기상청 **예보** → 분기 날씨 짐작 정확도 | 오차 9.2% 감소(분기 말 30일 이내 약 25%), 23개 분기 중 21개 개선, p = 0.0006 | ✅ 확인 |
> | 날씨 → **전력·비알코올음료·빙과** 물량 (전국, 2000~2025) | 전력 냉방 +1.8%/난방 +1.4%(100도일당), 비알코올음료 +3.6%, 빙과 +1.9% (8개 묶음 보정 통과) | ✅ 확인 |
> | 날씨 → 알코올음료·가정용 기기 출하, 연간 주거용 전력 | p = 0.09 ~ 0.65 | ✕ 확인 안 됨 |
> | 날씨로 물량을 **미리 짐작** (표본외 2021~2025, 분기 말 30일 전) | 날씨 없이 짐작한 것보다 낫지 않음, p = 0.86 (같은 기간 에너지 가격·코로나 이후 충격이 더 큼) | ✕ 확인 안 됨 |
> | 날씨 → 도시가스 5사 **영업이익** | 방향은 예상대로(+), p = 0.062 | △ 기준 미달 |
> | 날씨 → **매출** (가스·음료·의류·유통) | 4개 업종 모두 p ≥ 0.46 | ✕ 확인 안 됨 |
> | 지수 → **주가** | 실적 단계 미통과로 해석하지 않음 | — 보류 |
>
> 현재 근거로 말할 수 있는 범위: 날씨는 **가스·전력·비알코올음료·빙과** 물량을 움직이고, 예보를 쓰면 이번 분기 날씨 짐작이 정확해집니다. 다만 2021~2025년 표본외 검증에서 날씨만으로 물량을 미리 맞히는 정확도는 개선되지 않았습니다. 날씨는 가격·추세 정보와 함께 쓰는 보조 신호로 다시 검증할 단계입니다. 매출·주가에서는 날씨 효과가 확인되지 않았습니다. 투자 권유가 아닙니다.

## 1. 구조

```
[입력]   기상정보: 관측(ASOS 8개 도시, 1985~) · 기상청 중기예보 이력(2015~) · 평년(직전 30년)
         기업정보: 업종·공급지역·분기 실적(DART)
         업종 물량: 도시가스 시도별 판매량(가스공사) · 전력 판매량(EPSIS) · 음료·빙과·가전 출하지수(KOSIS)
         금융정보: 주가·거래량(FinanceDataReader) · 물가(ECOS)
[엔진]   날씨 민감도(패널 회귀, 부분 풀링) · 이번 분기 날씨 짐작(관측+예보+평년) · 상승확률 학습(로지스틱 vs GBM)
[지수]   기상수혜도 B · 신뢰도 C · 상승확률 P → 종합 SWI (0~100)
[활용]   관심종목·위험경고 · 대시보드 · 매일 자동 실행
[검증]   사전 등록 판정(연도 순열검정) · 데이터 품질 점검(이상 시 멈춤)
```

| 폴더·파일 | 역할 |
|---|---|
| `config.py` | 대상 종목·관측소·기간·기준온도, **사전 등록 판정 기준(`PREREG_*`)과 변경 이력** |
| `collect/` | 수집만 담당 (대상+기간 → 표준 형식, 한 종목이 실패해도 나머지 계속) — `kma_apihub.py`(기상청 API허브 관측·예보), `dart.py`, `prices.py`, `ecos.py` |
| `core/` | 날씨지수(`indices.py`), 품질 점검(`quality.py`), 패널(`panel.py`), 회귀(`regress.py`) |
| `swi/` | 지수 엔진(`inputs`·`engine`·`index`·`decision`·`event`), 판매량(`volume.py`), 사전 등록 판정·순열검정(`prereg.py`), 예보 가치 검증(`forecast_value.py`), 업종 물량 묶음 검정(`sector_volume.py`), 표본외 나우캐스트(`nowcast_oos.py`) |
| `system/` | DB(`db.py`), 일별 날씨 짐작(`nowcast.py`), 오늘의 지수·품질 게이트(`today.py`) |
| `run_collect.py` → `run_analysis.py` → `run_swi.py` | 수집 → 검정·판정 → 지수 백테스트 |
| `swi_system.py`, `dashboard.py`, `scripts/` | 운영(DB 적재·매일 실행·대시보드·윈도우 예약) |
| `tools/` | 판정 방식 보정 점검(합성 데이터) 스크립트와 결과 |
| `docs/` | 결론 문서·공유용 PDF |
| `tests/` | 손으로 계산한 기대값과 대조하는 테스트 64개 (`fixtures/`는 기상청 실제 응답 샘플, 인증키 없음) |

## 4. 판정 방식 — 사전 등록 (`config.PREREG_*`)

결론은 결과를 보기 전에 정한 기준으로만 냅니다. 기준을 적은 시각은 커밋 기록으로 남습니다. 나머지 회귀·백테스트 표는 탐색 자료입니다.
p값은 모두 **연도 순열검정 999회**로 구합니다. 날씨값을 해 단위로 다른 해와 바꿔 끼워 "날씨와 실적이 무관할 때 이 정도 결과가 얼마나 자주 나오나"를 직접 만드는 방법입니다.

| 등록 | 검정 | 통과 기준 | 결과 |
|---|---|---|---|
| 1차 (주 결과) | 업종마다 1개: 가스 ΔHDD(+), 음료 ΔCDD(+), 의류·유통 4분기 Δ기온(−) → 매출 성장률. 기업FE+분기·연도더미 | 4개 업종 BH 보정 q ≤ 0.10, 부호 일치 | 4개 모두 미통과 |
| 2차 | 1차 통과 업종만 SWI 업종 내 롱숏(왕복 30bp), 평가구간 | Newey-West t ≥ 2 | 해당 없음 |
| 추가 ① (1차 실패 뒤, 자료 받기 전) | 시도별 도시가스 판매량 성장률 ~ 그 지역 ΔHDD. 지역FE+분기더미 | 단측 p < 0.05, 계수 > 0 | 통과 |
| 추가 ② (①통과 뒤, 결과 보기 전) | 도시가스 5사 영업이익 변화 ~ ΔHDD. 기업FE+분기더미, 2023 제외 | 단측 p < 0.05, 계수 > 0 | 미통과 (p = 0.062) |
| 추가 ④ (자료 받기 전) | 업종 넓히기 8개 묶음: 전력(월별 전체 ~ 냉·난방도일, 연간 주거용 ~ 냉·난방도일), 알코올음료·낙농/빙과·비알코올음료·가정용 기기 출하지수 ~ 냉방도일. 분기더미, 전국 날씨 | 묶음 BH q ≤ 0.10, 부호 | 전력 2·비알코올음료·빙과 통과, 4개 미통과 |
| 추가 ⑤ (계산 전) | 표본외 나우캐스트: 통과한 물량 4개를 과거로 추정 → 2021~2025년 각 분기를 분기 말 30일 전에 짐작, 날씨 없는 짐작과 비교 | 분기 단위 단측 p < 0.05 | 미통과 (8/20 분기, p = 0.86) |
| 추가 ③ (계산 전) | 분기 HDD 짐작: 관측+예보+평년 vs 관측+평년, 8개 지점 난방 분기 2015Q1~2026Q1 | 분기 단위 단측 p < 0.05 | 통과 |

- **제외 규칙:** 국내 매출 비중이 50% 미만인 종목은 뺍니다. 현재는 미스토홀딩스(옛 휠라홀딩스, 2025-04 사명 변경)만 해당합니다. 수집은 계속하며, `SWI_INCLUDE_EXCLUDED=1` 로 실행하면 포함한 참고 버전이 나옵니다.
- **판정 방식 변경 (2026-11-09, 실데이터 결과 보기 전):** Driscoll-Kraay t 에서 순열검정으로 바꿨습니다. 효과가 없는 합성 데이터에서 DK 는 '하나라도 통과'가 35%, 순열검정은 11%(명목 10%)였습니다. 근거와 재현 방법은 `tools/README_calibration.md`에 있습니다.
- **판매량 자료 처리 (자료는 봤지만 검정 전에 결정):** 2023년은 8개 지역이 난방이 없는 3분기에도 22~28% 동시에 급감해서 뺐습니다(원인 미확인). 울산은 3분기 전년비 표준편차가 36%라서 "15% 초과 지역 제외" 규칙으로 뺐습니다. 처리 방식을 바꿔도 결론은 같았습니다(계수 0.051~0.077, 모두 p = 0.001).
- **일본 자료:** 한국 유효 분기가 부족한 업종에만 참고값으로 표시하고, 판정·점수에는 섞지 않습니다. 현재는 미사용입니다.

## 5. 모형과 그렇게 정한 이유

- **전년 동분기 대비:** 결과(매출·판매량·이익)와 날씨를 모두 전년 같은 분기와 비교합니다. 계절성이 자동으로 빠집니다. 영업이익은 음수가 될 수 있어 로그 대신 전년 매출로 나눕니다.
- **평년:** 해당 연도 *이전* 30년만 씁니다. 미래 값을 바꿔도 평년이 변하지 않는지 테스트로 확인합니다.
- **매출 대신 물량으로:** 매출은 가격(가스 원료비 연동·요금 조정, 1년 새 약 38% 인상 등)과 제품 구성에 가려 날씨 신호가 사라집니다. 같은 날씨 효과가 물량(판매량·출하지수)에서는 가스·전력·비알코올음료·빙과에서 확인됐습니다. 지수의 가스 민감도는 판매량 기반이고, 판매량을 쓸 수 없는 경동도시가스(울산)·지역난방공사는 매출 기반입니다.
- **예보 오차:** 실측했습니다(2015~2026년, 리드당 6~7만 건). 편향은 +0.35~0.46℃이고 자동 보정합니다. 오차는 3일 뒤 1.28℃, 10일 뒤 2.53℃이고, 인접한 날끼리 상관이 0.43~0.60입니다. 분기 합계 불확실성은 리드 간 공분산까지 더해 계산합니다. 독립으로 가정하면 약 1.5배 과소평가됩니다.
- **업종 안에서 비교:** 전 종목을 한 줄로 세우면 '계절별 업종 갈아타기'가 섞이므로, 점수와 포트폴리오는 업종 안에서 만듭니다.
- **데이터 품질은 실거래의 전제:** 기상 이상치, 0 이하 매출, 관측 5일 이상 정지, 주가 7일 이상 미갱신, 날씨로 설명 안 되는 판매량 급변이 있으면 계산을 멈추고 사유를 남깁니다.

| KOSIS 공개 품목에 음료·가전 없음 / 가정용 기기 2002년 1분기 +33% 급변 | 산업별 출하지수로 대체(계산 전) / 2002년 제외(검정 전) |

## 7. 알려진 한계

- 대상은 18개 종목, 2015~2025년입니다. 작은 효과는 통계적으로 잡기 어렵고, 상장 유지 종목만 대상이라 생존 편향이 있습니다.
- 도시가스 판매량은 회사별이 아니라 시도별 합계(가스공사 공급량)입니다.
- 전국형 기업은 6개 도시 평균 날씨를 씁니다. 실제 매출 지역 비중과 다를 수 있습니다.
- FinanceDataReader 등 무료 데이터는 개인 연구용입니다. 상업 서비스에는 사용권이 있는 유료 데이터가 필요합니다.
- 상승확률(P) 모델의 표본외 AUC는 0.45~0.53입니다. 예측력이 확인되지 않았습니다.

## 8. 일별 운영 (`swi_system.py daily`)

- **이번 분기 날씨 = 관측 + 예보 + 평년:** 분기 시작부터 어제까지는 실제 관측, 3~10일 뒤는 기상청 중기 기온예보(편향 보정), 나머지는 직전 30년 같은 날짜 평균(앞뒤 15일로 다듬음)입니다.
- **대시보드:** 오늘의 지수, 종목 상세(날씨 분해·추이), 검증(맨 위에 사전 등록 판정), 시스템 상태(실행 이력·데이터 신선도)로 구성됩니다.
- **품질 점검:** 걸리면 그날 지수를 내지 않고 실행 이력에 `halted`와 사유를 남깁니다.

## 9. 공개 웹 (Streamlit Community Cloud)

공개 웹에는 원자료·DB·주가를 올리지 않고, `public_snapshot/`의 계산 결과만 올립니다.
DB가 없는 곳에서 `dashboard.py`를 열면 이 폴더를 읽는 공개판(이번 분기 날씨 · 검증 · 데이터 기준일)으로 뜹니다. DB가 있는 PC에서는 기존 화면 그대로입니다.

```
python swi_system.py daily      # 최신 관측·예보로 계산
python swi_system.py publish    # public_snapshot/ 갱신 (마지막 daily 가 멈췄으면 만들지 않음)
# public_snapshot/ 을 GitHub에 올리면 웹이 다시 그려짐
```

스냅샷에 들어가는 것: 지역별 분기 날씨 짐작(기상청 공개자료에서 계산), 사전 등록 판정 요약표, 데이터 기준일. 들어가지 않는 것: 원자료, 주가와 종목 점수, 실행 로그, 인증키.

## 부록. 보류 중인 기능 — 날씨 리스크 스트레스 테스트 (`run_stress.py`)

이 시스템의 범위 밖이라 보류했습니다. 기온 모형(추세+계절+분기충격+일 단위 OU)으로 내년 날씨를 5,000번 시뮬레이션해 업종별 날씨 VaR·ES를 계산합니다. 회귀계수가 확인되지 않은 업종의 값은 의미가 없습니다.
